# Installing the agent

English | [简体中文](install.zh-CN.md)

The agent, `xnux-agent`, is a statically linked Go binary (amd64 / arm64) that supports Linux kernel ≥ 4.15. With systemd it runs as a service; without systemd it still runs, but service-crash monitoring is switched off automatically, and the console's server details page says so.

## One-line install

Without `--token` you get a local [black box](standalone.md) (standalone mode, no network). To report to Xnux, copy the install command from **Servers → Add server** in the console; it already includes the agent key and the reporting endpoint:

```sh
curl -fsSL https://github.com/xyfu/xnux-agent/releases/latest/download/install.sh | sudo sh -s -- --token xat_…
```

The script, the binaries and `SHA256SUMS` all come from this repository's [GitHub Releases](https://github.com/xyfu/xnux-agent/releases).

What the script does (source: [deploy/install.sh](../deploy/install.sh)):

1. Picks amd64 / arm64 from `uname -m` and downloads `xnux-agent-linux-<arch>` and `SHA256SUMS` (with curl or wget).
2. Verifies the checksum with `sha256sum` (or `shasum` / `openssl`). **On a mismatch it exits immediately and installs nothing.**
3. Installs to `/usr/local/bin/xnux-agent`, creates the symlink `/usr/local/bin/xnux` (the command-line tool), creates the `xnux` group, and writes `/etc/xnux/agent.yaml` (0600).
4. Writes a hardened systemd unit (`NoNewPrivileges`, `ProtectSystem=strict`, `MemoryMax=64M`, `CPUQuota=10%`), enables and starts it, then runs `xnux-agent --check` as a self-test.

Within a few seconds of installing, the console's install wizard shows the raw contents of the first report it received.

### Options

| Option | Effect |
| --- | --- |
| `--token xat_…` | The agent key generated by the console. Without it, the agent runs in standalone mode (records locally only). Can be omitted when updating to keep the existing config |
| `--endpoint URL` | Reporting endpoint: the server, or your [Cloudflare Worker](relay.md). Default `https://ingest.xnux.net` |
| `--version vX.Y.Z` | Install a specific version (default: latest) |
| `--base-url URL` | Download binaries from here (a mirror of the Release files) instead of GitHub Releases |
| `--dry-run` | After downloading and verifying, run `xnux-agent --dry-run --once` once and print what would be sent; **installs nothing and sends no data**, and does not need root |
| `--hide-hostname` | Replace the reported hostname with `host` |
| `--ca-file PATH` | Trust this CA when the reporting endpoint uses a private CA |
| `--least-privilege` | Run as the dedicated user `xnux` with a minimal capability set; see [least-privilege.md](least-privilege.md) |
| `--no-start` | Install but do not start |
| `--add-user USER` | Add USER to the `xnux` group so they can use the `xnux` command without sudo |
| `--no-prompt` | Don't ask (by default the script asks whether to add the current sudo user to the `xnux` group) |

### See what would be sent first

```sh
curl -fsSL https://github.com/xyfu/xnux-agent/releases/latest/download/install.sh | sh -s -- --dry-run
```

Any regular user can run this. The output is exactly the JSON the agent sends on each report (already redacted, with replacements highlighted in red); see [payload.md](payload.md) and [redaction.md](redaction.md).

## Updating

The console's "Update agent" panel gives the exact commands for your server. By hand:

```sh
curl -fsSL -o /tmp/xnux-install.sh https://github.com/xyfu/xnux-agent/releases/download/vX.Y.Z/install.sh
sha256sum /tmp/xnux-install.sh          # compare with the release's SHA256SUMS
sudo sh /tmp/xnux-install.sh --upgrade --version vX.Y.Z
xnux-agent version
```

`--upgrade` asks nothing and changes nothing but the binary: `/etc/xnux/agent.yaml` (with its agent key), the state and spool in `/var/lib/xnux` and the systemd unit stay as they are. The previous binary is kept as `/usr/local/bin/xnux-agent.prev`; if the new one does not start, it is put back and the script exits with an error. `sudo sh /tmp/xnux-install.sh --rollback` puts the previous version back by hand. With `cosign` installed, the script also checks the binary's signature. Re-running the plain install command also updates the agent (it rewrites the unit file). The agent **never updates itself** and has no channel for remote commands.

## Uninstalling

```sh
curl -fsSL https://github.com/xyfu/xnux-agent/releases/latest/download/uninstall.sh | sudo sh               # keep config and data
curl -fsSL https://github.com/xyfu/xnux-agent/releases/latest/download/uninstall.sh | sudo sh -s -- --purge # remove everything (including local events and metrics, and the xnux user and group)
```

After uninstalling, delete the server in the console; Xnux revokes its agent key and hard-deletes all of its data.

## Systems without systemd

The script installs the binary and config, and tells you to run it with your own init system:

```sh
/usr/local/bin/xnux-agent run --config /etc/xnux/agent.yaml
```

When the agent starts and finds no systemd, it disables service-crash monitoring and drops `systemd` from the reported `capabilities`; resource metrics, kernel events, security logs and suspicious-process scans work as usual.

## Verified distributions

This repository's CI `install` job runs [scripts/install-smoke.sh](../scripts/install-smoke.sh) on Ubuntu 20.04 / 22.04 / 24.04, Debian 12 / 13, Rocky Linux 9 and Alpine 3.20: a dry-run as a regular user installs nothing and sends nothing, and a tampered binary is rejected. The full install flow (install, first report, an update keeping config, least privilege, `uninstall --purge`) is verified in the Xnux service's CI against a systemd container for each distribution.

To run it locally:

```sh
make dist && IMAGE=debian:12 scripts/install-smoke.sh
```

## Verify the binary matches the source

Released binaries are reproducible builds (`-trimpath`, a pinned Go version, `-buildid=`, with version and commit injected via `-X`):

```sh
git clone https://github.com/xyfu/xnux-agent && cd xnux-agent && git checkout vX.Y.Z
make agent VERSION=vX.Y.Z COMMIT=$(git rev-parse --short HEAD)
sha256sum bin/xnux-agent-linux-*    # compare with the Release's SHA256SUMS and with /usr/local/bin/xnux-agent
```

Every file in a Release also has a cosign keyless signature (`.sig` + `.pem`):

```sh
cosign verify-blob --certificate xnux-agent-linux-amd64.pem --signature xnux-agent-linux-amd64.sig \
  --certificate-identity-regexp 'https://github.com/xyfu/xnux-agent/' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com xnux-agent-linux-amd64
```

On every run, the CI `reproducible` job builds in two ways (on the runner and in the official Go image) and compares the results, which are byte-for-byte identical.

## After installing

| To | Command |
| --- | --- |
| Check status and logs | `systemctl status xnux-agent`, `journalctl -u xnux-agent` |
| See what was just sent | `sudo cat /var/log/xnux/last_outgoing_payload.json` |
| Compare with what the server received | `sudo cat /var/log/xnux/last_outgoing_payload.sha256`, and compare with the hash shown on the console's transparency audit page |
| Self-test | `sudo xnux-agent --check` |
| View the effective config | `sudo xnux-agent --print-config` (the agent key shows only its last 4 characters) |

For all config options, see [deploy/agent.yaml.example](../deploy/agent.yaml.example).
