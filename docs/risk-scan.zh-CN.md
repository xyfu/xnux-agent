# 风险扫描

[English](risk-scan.md) | 简体中文

Xnux 探针会定期在你的服务器上检查少数几项容易被入侵利用的配置。扫描结果只留在你的服务器上，不会上传到 Xnux。探针只用它来判断：哪些安全信息值得告诉你。

## 为什么要扫描

任何连在公网上的服务器，每天都会被自动化程序尝试猜密码。如果你的服务器已经关闭了密码登录，这些尝试不可能成功，把它们当作告警发给你只会制造噪音。只有当攻击真的可能成功时，它才值得你关注。扫描就是用来做这个判断的。

## 扫描什么

| 检查项 | 读取的内容 |
| --- | --- |
| SSH 是否允许密码登录 | 运行 `sshd -T` 读取 SSH 服务的生效配置；如不可用，读取 `/etc/ssh/sshd_config` 及 `/etc/ssh/sshd_config.d/` |
| root 是否允许用密码登录 | 同上 |
| 数据库是否对公网开放（Redis、MongoDB、MySQL、PostgreSQL、Elasticsearch、Memcached） | `/proc/net/tcp` 与 `/proc/net/tcp6` 中正在监听的端口 |
| Docker API 是否对外暴露 | Docker 守护进程的启动参数（`/proc/<pid>/cmdline`）与 `/etc/docker/daemon.json` |

检查的数据库端口为 6379（Redis）、27017（MongoDB）、3306（MySQL）、5432（PostgreSQL）、9200（Elasticsearch）与 11211（Memcached）；监听在所有网卡（`0.0.0.0` 或 `::`）或公网地址上即视为对公网开放，不读取防火墙规则。Docker API 以未加 TLS 的 `tcp://` 监听在回环以外的地址上，或有程序监听 2375 端口，即视为对外暴露。

## 不扫描什么

探针不会读取：密码文件（`/etc/shadow`）、任何私钥、你的应用配置文件、环境变量。

## 什么时候扫描

- 探针启动时，以及每天一次
- `/etc/ssh/` 下的配置文件发生变化时（最后一次变化 10 秒后）
- 数据库端口：每 5 分钟随进程巡检一起检查

每次扫描只需几毫秒，不会影响服务器性能。

## 扫描结果会导致上报什么

| 如果发现 | Xnux 会开始收到 |
| --- | --- |
| SSH 允许密码登录 | SSH 暴力破解与密码喷洒事件 |
| root 允许用密码登录 | 同上，并且告警级别更高 |
| 数据库对公网开放 | 有公网地址连接该数据库时的告警（含连接数与已隐去末段的来源网段） |
| Docker API 对外暴露 | 有外部地址连接 Docker API 时的告警 |

无论扫描结果如何，以下内容始终上报：密码被猜中后的登录成功、root 用密码登录成功，以及每小时的攻击次数汇总（只有次数、来源数和常被尝试的用户名）。

需要坦白的一点：如果 Xnux 收到了某类事件，就能推断出对应的风险存在，比如收到 SSH 爆破事件，就意味着这台服务器允许密码登录。但 Xnux 不持有你服务器的 IP 地址，这条信息无法用来定位你的服务器。风险消失后，探针会自动停止相关上报。

## 查看扫描结果

在服务器上运行 `xnux status`，可以看到最近一次扫描的时间、每一项的结果，以及当前因此开启了哪些上报。

## 验证实际上报的内容

- 运行 `xnux-agent --dry-run`，在终端中查看将要上报的每一条数据，不会发送任何内容。
- 查看 `/var/log/xnux/last_outgoing_payload.json`，这是最近一次实际发出的内容。

扫描代码完全开源，位于公开仓库 [xyfu/xnux-agent](https://github.com/xyfu/xnux-agent) 的 [`internal/riskscan`](../internal/riskscan) 目录。

## 关闭风险扫描

在 `/etc/xnux/agent.yaml` 中设置：

```yaml
collectors:
  riskscan: false
```

然后重启探针。关闭后，探针不再读取上述配置；Xnux 只会在密码被猜中后登录成功、root 用密码登录成功时告警，并继续收到每小时攻击汇总；不再收到暴力破解、数据库公网访问和 Docker API 访问事件。
